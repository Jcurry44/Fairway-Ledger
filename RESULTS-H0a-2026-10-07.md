## What changed
- `lib/snapshots.js` (new, UMD, `window.FairwaySnapshots`): `create({storage,...})` -> `list, prune, pruneAutosaves, take, read, remove, writeGuarded, usageBytes`. app.js snapshot code now delegates to it (same key prefix, same payload shape, same 20 cap, same 10-min throttle and dedupe, so old snapshots keep working).
- Eviction order: autosaves first (oldest first), then other reasons; the newest 3 snapshots are never evicted. New byte cap `SNAPSHOT_MAX_BYTES = 2,500,000`.
- `saveState()` quota guard (`writeGuarded`): write, else prune by 5 and retry, else drop autosaves (newest 3 kept) and retry, else drop everything but the newest 3 and retry, else `storageBlocked`. The canonical key `fairwayLedger.v1` is never removed or cleared; a failed `setItem` leaves the old value intact. In-memory state and the `inProgressRound.v1` draft are untouched.
- Blocking red banner on every tab while blocked: "Not saved - storage is full. Export now, then delete old snapshots." with **Export** (serializes in-memory state) and **Free space** (removes autosave snapshots only, retries the save). `beforeunload` warns while blocked. Banner clears itself on the next successful save.
- Same guard on `mergeNewDefaultCourses`; `writeBackupMeta` is now try/catch (it ran inside export and import paths and could throw). Also guarded two unguarded UI-pref writes that aborted app init on a full disk (`setActiveTab` -> `fairwayLedger.activeTab`, brief-collapsed flag).
- Profile panel: "Storage used: X MB of about 5 MB".
- `lib/course-catalog.js` (moved from `data/courses.js` with `git mv`, content unchanged): `window.FairwayCourseCatalog = { courses, version }`, plus legacy alias `window.__golfCourseCatalog`. app.js reads `FairwayCourseCatalog`. `data/courses.js` is gone (index.html, sw.js, README, ARCHITECTURE updated).
